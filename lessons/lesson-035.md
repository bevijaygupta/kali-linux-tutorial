## Important concepts

### Brute force by name

DNSmap prepends candidate labels from a wordlist to the target domain and queries DNS for each. A hit means the name resolves, not necessarily that it hosts a live or interesting service. The technique is simple and still effective because organizations forget old names.

### Wordlists are reusable assets

The same candidate names used for subdomain discovery often reappear in virtual-host discovery, content discovery and password guessing. Building a curated list for a target type is a skill that compounds across engagements.

## Practical notes

Run DNSmap only against domains you own or are authorized to test.

| Command | What it does |
| --- | --- |
| `dnsmap example.com` | Run a default subdomain scan with the built-in wordlist. |
| `dnsmap example.com -w subdomains.txt` | Use a custom wordlist of candidate labels. |
| `dnsmap example.com -r results.txt` | Save the results to a file for review. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is the difference between DNSmap and Dnsenum?

Both enumerate DNS. Dnsenum bundles record lookups and zone-transfer attempts with brute forcing; DNSmap focuses on wordlist-driven subdomain discovery.

### What wordlist should I start with?

The built-in list in Kali is a reasonable start. A smaller, target-relevant list often produces cleaner results than a huge generic list.
