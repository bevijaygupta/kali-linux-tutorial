## Important concepts

### Modes encode assumptions

Single mode derives candidates from account information, wordlist mode tries a supplied list with optional rules, and incremental mode explores a character space. Choosing a mode is choosing which guesses you believe are most likely.

### Cracking files uses the same pipeline

Tools such as zip2john extract a verifiable hash from a protected archive. John then attacks that hash. The archive itself is not decrypted by brute force; the password is recovered, then used normally.

## Practical notes

Use hashes and archives you created in the lab. Install the jumbo package if a format is not recognised.

| Command | What it does |
| --- | --- |
| `john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt` | Run a wordlist attack against a lab hash file. |
| `john --incremental hashes.txt` | Run an incremental brute-force attack (slow). |
| `john --show hashes.txt` | Print recovered passwords. |
| `zip2john protected.zip > zip.hash` | Extract a verifiable hash from a ZIP archive. |
| `john --wordlist=/usr/share/wordlists/rockyou.txt zip.hash` | Crack the extracted archive hash. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Why does John not recognise my hash?

The format may need an explicit --format option, or the file may contain extra text. Use the matching *2john tool where possible.

### What is the fastest John mode?

It depends on the target. Wordlist mode with good rules is often fastest for human-chosen passwords; incremental mode is exhaustive and slow.
