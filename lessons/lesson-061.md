## Important concepts

### Packets, frames and streams

Wireshark shows individual frames but can reconstruct a higher-level conversation. Following a TCP stream joins the packets of one connection so you can read the application exchange rather than inspecting it packet by packet.

### Display filters are applied after capture

Display filters such as ip.addr == 192.168.56.101 or http hide packets without discarding them. Capture filters decide what is recorded in the first place, which is the subject of the next chapter.

## Practical notes

Capture on your own lab interface. Filter examples assume a lab subnet; adjust addresses to match.

| Command | What it does |
| --- | --- |
| `sudo wireshark` | Launch Wireshark with capture permissions. |
| `ip.addr == 192.168.56.101` | Display filter for traffic to or from one host. |
| `http` | Display filter for HTTP traffic. |
| `tcp.port == 80` | Display filter for TCP port 80. |
| `Follow > TCP Stream` | Reassemble a TCP conversation from the packet context menu. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Why can't Wireshark see other devices' traffic?

On a switched network, unicast frames are delivered only to the destination port. You need your own traffic, a mirrored port or an authorized redirection technique.

### What is the difference between a capture filter and a display filter?

A capture filter decides what is recorded. A display filter hides packets from the recorded set without deleting them.
