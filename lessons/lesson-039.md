## Important concepts

### Port states are inferences

Nmap interprets replies, or the absence of replies. Open means a service accepted the probe, closed means the host replied with a rejection, and filtered usually means a firewall dropped the packet. A filtered result is not proof that no service exists.

### Timing changes noise

Timing templates trade speed for reliability and stealth. -T4 is common on fast, reliable lab networks. Higher templates send more aggressively and are more likely to overwhelm weak services or trigger defences.

## Practical notes

Practise on your own lab host and compare how each option changes output and runtime.

| Command | What it does |
| --- | --- |
| `sudo nmap -sA 192.168.56.101` | ACK scan to probe firewall filtering behaviour. |
| `sudo nmap -sF 192.168.56.101` | FIN scan, which may bypass some simple filters. |
| `sudo nmap -sX 192.168.56.101` | Xmas scan with FIN, PSH and URG flags set. |
| `nmap -T4 192.168.56.101` | Use an aggressive-but-reasonable timing template in a lab. |
| `sudo nmap -A 192.168.56.101` | Enable OS detection, version detection, scripts and traceroute. |
| `nmap -oA labscan 192.168.56.101` | Save normal, XML and grepable output with one base name. |
| `nmap --script http-title -p 80 192.168.56.101` | Run a single NSE script against a web port. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What does the -A flag do?

It enables several detections at once: OS detection, version detection, script scanning and traceroute. It is powerful but noisy.

### What is the Nmap Scripting Engine?

NSE runs Lua scripts that extend Nmap for tasks such as service discovery, enumeration and basic vulnerability checks.
