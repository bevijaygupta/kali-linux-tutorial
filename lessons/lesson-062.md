## Important concepts

### Filter early to save space

A busy interface can produce gigabytes quickly. Capture filters such as host 192.168.56.101 and port 80 reduce the data at the source, which keeps files small and analysis focused. The trade-off is that excluded traffic is gone permanently.

### Plaintext has a signature

HTTP requests, form posts and many legacy protocols are readable in a capture. Seeing a username and password in cleartext is a powerful demonstration of why TLS matters, and a reminder to treat packet captures as sensitive evidence.

## Practical notes

Start with a narrow capture filter, reproduce one action in your lab, then stop and save.

| Command | What it does |
| --- | --- |
| `host 192.168.56.101` | Capture filter limited to one host. |
| `tcp port 80` | Capture filter for HTTP traffic. |
| `File > Save As` | Save the capture as a .pcap or .pcapng file. |
| `tshark -r capture.pcap -Y http` | Read a saved capture from the command line if tshark is installed. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Which filter should I use first?

Start with a capture filter for the specific host and port you need. It keeps the file small and analysis focused.

### Can I capture Wi-Fi traffic?

Only traffic your adapter can see. Capturing other wireless clients usually requires monitor mode and, for encrypted networks, additional material such as the handshake.
