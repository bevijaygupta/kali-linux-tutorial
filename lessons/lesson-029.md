## Important concepts

### Order matters

Tor must be running before a wrapped tool attempts a connection. If the SOCKS port is closed, a permissive Proxychains configuration may fall back to a direct connection, which defeats the purpose. Verify Tor status, then test the chain with a simple request.

### Leak checks

Check your public address from inside the wrapped command, not from a separate browser. DNS resolution, IPv6 traffic and tools that bypass the wrapper are common leak paths, so a single IP check is a starting point rather than a full audit.

## Practical notes

Follow the order shown in the tutorial and confirm each step before running a security tool.

| Command | What it does |
| --- | --- |
| `sudo systemctl start tor` | Start the Tor service. |
| `systemctl status tor --no-pager` | Confirm the service is active. |
| `proxychains4 -q curl -s https://ifconfig.me` | Check the address seen when traffic passes through the chain. |
| `proxychains4 -q curl -s https://check.torproject.org` | Confirm the request is using Tor. |

## FAQ

### Why does my real IP still appear with Proxychains?

Tor may not be running, the proxy entry may be wrong, or the tool may bypass the wrapper. Check the service, the port and the tool's networking behaviour.

### Is Proxychains plus Tor enough for anonymity?

No. It only covers wrapped processes. Browser fingerprinting, logins, DNS and unencrypted traffic can still expose you.
