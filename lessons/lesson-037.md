## About this chapter

Chapter 37 prepares you to scan by first understanding your own network. It shows how to find your IP and MAC address with ifconfig and the modern ip a command, how to read the routing table and default gateway with route -n, what Nmap is, and how to run a first scan against your own lab network.

## Important concepts

### Know your starting point

Your interface address, subnet mask and default gateway define what your machine can reach directly. Without them, scan results are hard to interpret and you may accidentally probe a network outside your lab.

### Host discovery before port scanning

A ping sweep such as nmap -sn identifies live hosts without scanning ports. Starting here narrows the target list and reduces unnecessary traffic, which matters for both performance and authorization.

## Practical notes

Run these inside your lab VM and confirm the results match your virtual network settings.

| Command | What it does |
| --- | --- |
| `ip a` | Show interfaces and addresses (modern replacement for ifconfig). |
| `ifconfig` | Show interface details if net-tools is installed. |
| `route -n` | Display the routing table and default gateway. |
| `nmap -sn 192.168.56.0/24` | Discover live hosts in your own lab subnet without port scanning. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is the difference between ifconfig and ip a?

Both show interface information. ip a is part of the modern iproute2 suite and is available by default on current Linux systems; ifconfig comes from the older net-tools package.

### What is a default gateway?

The router your machine sends traffic to when the destination is not on the local subnet.
