## Important concepts

### adduser versus useradd

adduser is a friendly interactive wrapper that creates a home directory, sets a password and configures defaults. useradd is the low-level utility and does much less unless you pass explicit options. For normal administration, adduser is harder to get wrong.

### su versus sudo

su switches your identity to another account and asks for that account's password. sudo runs a single command with elevated privileges and asks for your own password, with the action logged. sudo with least privilege is usually safer and more auditable.

## Practical notes

Run these inside your lab VM and inspect the resulting entries in /etc/passwd.

| Command | What it does |
| --- | --- |
| `sudo adduser student` | Create a new user with a home directory and password prompt. |
| `sudo passwd student` | Set or change the user's password. |
| `su - student` | Start a login shell as student with their environment. |
| `sudo -l` | List the commands your account may run with sudo. |
| `id` | Show your user ID, group ID and group memberships. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is the difference between su and su -?

su keeps much of your current environment. su - starts a full login shell for the target user, including their home directory and environment variables.

### Should I work as root all the time?

No. Use a normal account and sudo for specific tasks. Permanent root sessions make accidental damage and credential exposure far more likely.
