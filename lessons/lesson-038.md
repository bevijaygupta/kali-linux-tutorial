## Important concepts

### Scan types reflect different packets

A SYN scan (-sS) sends a TCP SYN and infers state from the reply without completing the handshake; it usually needs root. A TCP connect scan (-sT) completes the handshake, works without raw sockets and is easier to log. A UDP scan (-sU) sends UDP probes and is slow because many services do not reply.

### Ports and services

Nmap's default scan covers the 1000 most common TCP ports. -p selects specific ports and -p- covers all 65535. -sV probes open ports to identify the service and version, which is what turns a list of open ports into useful reconnaissance.

## Practical notes

Use a lab target such as a Metasploitable VM. Replace addresses and ports with your own lab values.

| Command | What it does |
| --- | --- |
| `nmap 192.168.56.101` | Scan the 1000 most common TCP ports on one host. |
| `nmap 192.168.56.0/24` | Scan a lab subnet. |
| `sudo nmap -sS 192.168.56.101` | Run a SYN scan (root required). |
| `nmap -sT 192.168.56.101` | Run a TCP connect scan without raw sockets. |
| `sudo nmap -sU -p 53,161 192.168.56.101` | Scan selected UDP ports. |
| `nmap -sV -p 22,80,443 192.168.56.101` | Detect service versions on chosen ports. |
| `sudo nmap -O 192.168.56.101` | Attempt operating system detection. |
| `nmap -oN scan.txt 192.168.56.101` | Save normal-format output to a file. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is the difference between -sS and -sT?

-sS uses a half-open SYN scan and usually requires root. -sT completes the TCP handshake and works as a normal user, but is easier for the target to log.

### Why is a UDP scan so slow?

Many UDP services do not respond to probes, so Nmap must wait for timeouts to decide a port is open|filtered.
