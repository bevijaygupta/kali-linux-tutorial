## Important concepts

### Attack surface begins locally

Unnecessary services, world-writable files, weak sudo rules and stale packages are common weaknesses. An audit inventories what is running and who can change it, which is the same information an attacker uses after access.

### Automation needs interpretation

Lynis produces a hardening index and many suggestions. The score is less important than the specific findings: critical exposures first, then configuration hardening, then informational advice.

## Practical notes

Audit your own VM. Review each finding before changing anything.

| Command | What it does |
| --- | --- |
| `sudo -l` | Show sudo permissions for your account. |
| `find / -xdev -perm -4000 -type f 2>/dev/null` | List SUID binaries on the root filesystem. |
| `ss -tulpn` | Show listening TCP and UDP sockets with processes. |
| `apt list --upgradable` | List packages with available updates. |
| `sudo lynis audit system` | Run a full local system audit. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What does the Lynis hardening index mean?

It is a rough score of how well the system follows hardening guidance. It helps track progress but is not a certification or a guarantee of security.

### Should I run a security audit on someone else's server?

Only with authorization. Even read-only checks can expose sensitive configuration and may violate policy or law without permission.
