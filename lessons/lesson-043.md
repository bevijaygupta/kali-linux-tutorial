## Important concepts

### Three delivery patterns

Reflected XSS bounces input straight back in a response. Stored XSS persists input, such as a comment, and affects every viewer. DOM-based XSS occurs when client-side JavaScript writes untrusted data into the page without safe handling.

### Defence is contextual encoding

Output must be encoded for the context where it appears: HTML body, attribute, URL or script. Input validation helps but is not sufficient. Content Security Policy, HttpOnly cookies and framework auto-escaping reduce impact and likelihood.

## FAQ

### Is XSS dangerous if the site has no login?

Yes. Script execution can still redirect users, alter content, mine data in the page, or attack visitors through their browsers.

### Does a web application firewall fix XSS?

A WAF can reduce some attacks but is not a substitute for correct output encoding. Bypasses are common.
