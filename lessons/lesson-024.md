## Important concepts

### What is inside a .ovpn file

An OpenVPN profile contains the remote server, protocol, port, certificates or key references and routing directives. Treat it as sensitive configuration: it may include credentials or private keys and should not be committed to a public repository.

### Verify the tunnel

After connecting, check that your public IP changed and that DNS queries resolve through the tunnel. A leaked DNS resolver can reveal the sites you visit even while web traffic uses the VPN.

## Practical notes

Use a profile from a provider you trust and keep it outside the repository, for example in a directory excluded by .gitignore.

| Command | What it does |
| --- | --- |
| `sudo apt update && sudo apt install openvpn` | Install the OpenVPN client. |
| `sudo openvpn --config client.ovpn` | Connect using the profile. Keep the terminal open. |
| `curl -s https://ifconfig.me` | Check the public IP address in use. |
| `Ctrl+C` | Disconnect the foreground OpenVPN process. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Can I use any .ovpn file?

Only one issued by a provider or administrator you trust. A profile points your traffic at a server, so an unknown profile can intercept it.

### Why does OpenVPN fail with a TLS error?

Common causes include an expired profile, a wrong system clock, a blocked UDP port or a certificate mismatch. Check the client log for the first error rather than the last.
