Chapter 75 returns to offense with browser exploitation. It distinguishes browser attacks from network exploits, lists vectors such as outdated plugins, malicious scripts and drive-by downloads, sets up BeEF in a lab, hooks a test browser, uses Metasploit against an outdated browser, delivers a payload, and explains why updates, script blockers and awareness defeat most of these attacks.

## Important concepts

### The browser is the target

Browser exploitation abuses the client rather than a network service. It often relies on outdated components or on convincing a user to visit a crafted page, which is why patching and script control matter more than network firewalls alone.

### BeEF demonstrates client-side risk

BeEF hooks a browser through injected JavaScript and exposes modules that show what page-level control can do. It is a demonstration framework: the value is understanding impact and defences, not attacking real users.

## Practical notes

Use intentionally outdated browser instances in an isolated lab. BeEF is generally started as a service on Kali.

| Command | What it does |
| --- | --- |
| `sudo systemctl start beef-xss` | Start the BeEF service. |
| `sudo beef-xss` | Launch BeEF with the packaged configuration if the service is not used. |
| `http://127.0.0.1:3000/ui/panel` | Open the BeEF control panel locally. |
| `msfconsole` | Start Metasploit for a lab browser exploit module. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What does it mean to hook a browser?

A malicious or test page loads JavaScript that maintains a connection to the BeEF server, allowing the operator to run modules in that page context.

### How do I defend against browser exploitation?

Keep the browser and plugins updated, remove unused extensions, use script blockers and enable automatic updates. User awareness reduces social-engineering success.
