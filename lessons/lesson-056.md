## About this chapter

## Important concepts

### Shadow files exist for a reason

Historically, password hashes lived in /etc/passwd, which every user can read. Modern systems move them to /etc/shadow, readable only by root. That change makes offline cracking require privileged access first.

### Windows SAM

The SAM database stores local account password material and is locked while Windows runs. Authorized forensic acquisition uses supported methods and produces hash formats that cracking tools understand, such as NTLM.

## Practical notes

Demonstrations require a lab VM you own and administrative access. Commands below use a copy of the files, not the live originals.

| Command | What it does |
| --- | --- |
| `sudo cp /etc/passwd /etc/shadow /tmp/` | Copy the files in an authorized lab for offline review. |
| `unshadow /tmp/passwd /tmp/shadow > combined.txt` | Merge passwd and shadow into a John-compatible file. |
| `john --wordlist=/usr/share/wordlists/rockyou.txt combined.txt` | Crack the combined lab hashes. |
| `john --show combined.txt` | Show recovered lab passwords. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Why can a normal user read /etc/passwd but not /etc/shadow?

/etc/passwd contains account information and is world-readable. /etc/shadow contains password hashes and is restricted to root.

### What is unshadow used for?

It combines the account data in passwd with the hashes in shadow so John the Ripper can associate each hash with a username.
