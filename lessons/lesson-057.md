## About this chapter

Chapter 57 applies the extract-then-crack workflow to archives and documents. It explains why protected files need a different approach, extracts hashes from ZIP and RAR files with zip2john and rar2john, cracks them with John and a wordlist, extends the method to PDFs with pdf2john, and discusses choosing a context-aware wordlist.

- How file context guides wordlist selection

## Important concepts

### Verification without decryption

Archive formats store enough information to test a candidate password without decrypting the whole file. The *2john helpers convert that information into a hash line John can attack efficiently.

### Context narrows the search

A file from a named project, client or year gives clues for a targeted wordlist or rule set. Blind brute force against modern encryption is rarely practical; context and wordlist quality decide the outcome.

## Practical notes

Create your own password-protected test archives. The helpers ship with John the Ripper jumbo.

| Command | What it does |
| --- | --- |
| `zip2john protected.zip > zip.hash` | Extract a verifiable hash from a ZIP file. |
| `rar2john protected.rar > rar.hash` | Extract a hash from a RAR file. |
| `pdf2john protected.pdf > pdf.hash` | Extract a hash from a PDF. |
| `john --wordlist=/usr/share/wordlists/rockyou.txt zip.hash` | Crack the extracted hash with a wordlist. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Can John open the archive directly?

Not usually. You extract a hash with the matching *2john helper, crack the password, then use the password with the normal extraction tool.

### Does this work on every encrypted file?

Only formats with a supported extraction helper. Strong encryption and long random passwords can make recovery impractical.
