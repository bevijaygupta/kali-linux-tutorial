## About this chapter

Chapter 42 introduces vulnerability analysis with Nikto. It explains how scanning differs from exploitation, runs Nikto against an owned test site, demonstrates options for ports, SSL and output files, and then focuses on reading results, recognising false positives and prioritising findings.

## What you will learn

- What a Nikto scan can and cannot tell you
- How vulnerability analysis differs from exploitation
- How to run a first Nikto scan against a lab site
- How to select ports, enable SSL checks and save output
- How to separate real findings from false positives
- How to prioritise remediation work

## Important concepts

### Scanning is not exploitation

Nikto sends requests and compares responses against a large database of known files, headers and misconfigurations. It reports potential issues, not proof of exploitability. Confirming impact is a separate, authorized step.

### Triage beats volume

A long Nikto report is not a long list of urgent problems. Prioritise exposed administrative interfaces, outdated components with known exploits, sensitive files and missing security headers in that order, and verify each item manually.

## Practical notes

Target an intentionally vulnerable lab app such as DVWA or a test server you control.

| Command | What it does |
| --- | --- |
| `nikto -h http://192.168.56.101` | Scan a lab web server on the default port. |
| `nikto -h https://192.168.56.101 -ssl` | Force SSL/TLS checking. |
| `nikto -h 192.168.56.101 -p 8080` | Scan a non-standard port. |
| `nikto -h 192.168.56.101 -o nikto.txt` | Save the report to a file. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Does Nikto exploit vulnerabilities?

No. It performs non-intrusive checks and reports potential issues. Exploitation is a separate phase that requires explicit authorization.

### Why does Nikto report outdated software that is actually patched?

It often relies on banners and headers. Backported patches can leave version strings unchanged, so verify the finding manually.
