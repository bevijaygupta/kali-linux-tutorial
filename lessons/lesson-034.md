## About this chapter

Chapter 34 automates the manual DNS work from the previous lesson with Dnsenum. It shows how to run the tool against a domain, how it uses wordlists to find subdomains, how to read the output, and how to combine it with other reconnaissance data.

## What you will learn

- How Dnsenum automates DNS enumeration
- How to run Dnsenum against an authorized domain
- How subdomain discovery uses wordlists
- How to read name server, mail and host records in the output
- How to combine Dnsenum results with manual dig queries
- Why noisy enumeration needs rate and scope control

## Important concepts

### Automation accelerates repetition

Dnsenum performs record lookups, zone-transfer attempts (where allowed) and subdomain brute force with a wordlist. The wordlist determines which names are tried, so a focused list is usually more useful than a massive generic one.

### Validate findings

Automated output can contain stale records and false positives. Confirm interesting hosts with dig or a direct connection before treating them as live parts of the target's infrastructure.

## Practical notes

Use a domain you own. The tool is available in Kali by default.

| Command | What it does |
| --- | --- |
| `dnsenum example.com` | Run a default enumeration against an authorized domain. |
| `dnsenum --enum example.com` | Run the more complete enumeration preset. |
| `dnsenum -f /usr/share/dnsenum/dns.txt example.com` | Use a specific subdomain wordlist. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Does Dnsenum perform zone transfers?

It attempts them and reports the result. Most correctly configured name servers refuse unauthorized transfers.

### Why are some discovered subdomains unreachable?

DNS records can point to retired, internal or unresponsive hosts. Verify each candidate before drawing conclusions.
