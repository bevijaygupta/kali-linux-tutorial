## Important concepts

### Read before you run

Cloning a repository downloads code, and running its installer executes that code with your privileges. Always read the README, inspect the install script and check recent activity before running tools from GitHub, especially as root.

### Verify the change

A tool reporting that it started is not proof that traffic is routed through Tor. Compare your public IP and check the Tor Project's detection page before and after enabling it, then disable it and confirm the original path returns.

## Practical notes

Use a lab VM. Commands follow the workflow demonstrated in the chapter; the exact repository URL is shown in the video.

| Command | What it does |
| --- | --- |
| `sudo apt update && sudo apt install git` | Install Git if it is not already present. |
| `git clone <repository-url>` | Download the AnonSurf repository shown in the tutorial. |
| `less README.md` | Read the documentation before installing anything. |
| `sudo anonsurf start` | Start routing through Tor, as demonstrated. |
| `sudo anonsurf status` | Check whether the service reports an active state. |
| `sudo anonsurf stop` | Stop routing and restore normal networking. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Does AnonSurf make me completely anonymous?

No. It routes system traffic through Tor, which hides your IP from destinations, but identity leaks through logins, browser fingerprints and misconfiguration are still possible.

### Why is git clone used in this chapter?

It is the standard way to download source code from GitHub and is a skill you will reuse for many security tools.
