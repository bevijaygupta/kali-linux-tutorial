## About this chapter

## Important concepts

### A wrapper, not a tunnel

Proxychains hooks network calls in the program it launches and sends them to the configured proxies. It only affects programs started through it. Other traffic on the system keeps using the normal route unless you redirect it separately.

### Chain modes

Strict mode uses every proxy in order and fails if one is unavailable. Dynamic mode tries proxies in sequence to establish a working chain. Random mode selects proxies randomly. For Tor, a single local SOCKS entry on port 9050 is the usual configuration.

## Practical notes

Edit the configuration only after backing it up, and test with a harmless request before using security tools.

| Command | What it does |
| --- | --- |
| `sudo cp /etc/proxychains4.conf /etc/proxychains4.conf.bak` | Back up the configuration first. |
| `sudo nano /etc/proxychains4.conf` | Review chain mode and the proxy list. |
| `sudo systemctl start tor` | Ensure Tor is running for the SOCKS entry. |
| `proxychains4 curl -s https://check.torproject.org` | Test whether requests use the Tor circuit. |
| `proxychains4 nmap -sT -Pn 192.168.1.10` | Run a TCP connect scan through the chain in your lab. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Why does Nmap fail through Proxychains?

SYN scans and raw-packet features do not translate cleanly to a SOCKS proxy. Use TCP connect scans with -sT and expect reduced accuracy.

### Does Proxychains apply to my whole system?

No. It only affects processes launched through the proxychains command.
