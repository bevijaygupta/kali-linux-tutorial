## About this chapter

Chapter 33 moves from footprinting concepts to DNS reconnaissance. It explains what DNS enumeration is, which records matter during an assessment, and how to query them manually with dig and nslookup before moving to automated Kali tools. Subdomains, mail servers and name servers are the focus.

## What you will learn

- What DNS enumeration is and why it matters in reconnaissance
- Which DNS record types reveal useful infrastructure details
- How to query records with dig
- How to use nslookup for basic lookups
- How subdomains, MX and NS records expand the attack surface
- How to stay inside an authorized scope while enumerating

## Important concepts

### DNS is a map of the organization

A, AAAA, MX, NS, TXT and CNAME records reveal where services live, who handles mail, which name servers are authoritative and which third parties are involved. TXT records can also expose verification tokens and mail security policy.

### Manual before automated

Running dig and nslookup by hand teaches you what the automated tools are doing and helps you validate their output. It also produces evidence you can explain in a report.

## Practical notes

Query a domain you own or a public example domain; do not enumerate third parties without permission.

| Command | What it does |
| --- | --- |
| `dig example.com A` | Resolve the domain's IPv4 address. |
| `dig example.com MX` | List mail exchangers for the domain. |
| `dig example.com NS` | List authoritative name servers. |
| `dig example.com TXT` | Show TXT records such as SPF and verification entries. |
| `nslookup example.com` | Perform a simple forward lookup. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is the difference between dig and nslookup?

Both query DNS. dig provides more detailed output and is preferred for troubleshooting and scripting, while nslookup is simpler and available on many platforms.

### Which DNS record reveals mail servers?

MX records list the mail exchangers responsible for accepting email for the domain.
