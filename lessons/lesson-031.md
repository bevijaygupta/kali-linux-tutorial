## Important concepts

### Vendor prefixes

The first three bytes of a MAC address identify the vendor (the OUI). A fully random address may look like an unknown device, while a same-vendor random address blends in with other hardware from that manufacturer. Both are presentation choices, not anonymity guarantees.

### State before change

Most failures come from trying to change an address on an interface that is up, or from using the wrong interface name. Bring it down, change the address, verify, then bring it up.

## Practical notes

Check each option against your own interface in a lab VM.

| Command | What it does |
| --- | --- |
| `macchanger -s eth0` | Show the current and permanent MAC address. |
| `sudo macchanger -r eth0` | Set a random MAC address. |
| `sudo macchanger -A eth0` | Set a random address within the same vendor range. |
| `sudo macchanger -m 00:11:22:33:44:55 eth0` | Set a specific custom address. |
| `sudo macchanger -p eth0` | Restore the permanent address. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What does macchanger -A do?

It sets a random MAC address while keeping the same vendor prefix as the original interface.

### Does the change survive a reboot?

No. MAC changes are temporary unless you configure them to run at boot, which is not recommended for normal use.
