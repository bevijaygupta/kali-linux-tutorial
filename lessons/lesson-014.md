## About this chapter

Linux remembers the commands you type, and Chapter 14 shows how to use that record. It covers viewing history, re-running commands with !! and history numbers, clearing the list with history -c, and finding where a program lives with whereis. It also compares whereis, which and locate.

## What you will learn

- How to view your shell command history
- How to re-run the last command or a specific numbered command
- What history -c clears and what it does not
- How whereis locates a program's binary, source and manual files
- The difference between whereis, which and locate
- When each of these commands is genuinely useful

## Important concepts

### History is convenience and evidence

The shell stores recent commands in memory and writes them to a history file. That is useful for repeating work, but it also means sensitive commands can persist in your account. Clearing history removes the list, not every trace written elsewhere by other tools or logging systems.

### Three different search tools

which reports the executable that your shell would run from PATH. whereis searches standard locations for binaries, source and manuals. locate searches a filesystem index. They answer different questions, so choosing the right one saves time.

## Practical notes

Use history deliberately and avoid storing secrets in commands.

| Command | What it does |
| --- | --- |
| `history` | Show recent commands with line numbers. |
| `!!` | Re-run the previous command. |
| `!42` | Re-run command number 42 from history. |
| `history -c` | Clear the in-memory history list. |
| `whereis nmap` | Locate the binary and manual page for nmap. |
| `which python3` | Show which python3 your PATH resolves to. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Does history -c delete the history file?

It clears the current session's list. The history file may still contain earlier commands until it is overwritten or removed.

### Why do whereis and which return different paths?

which follows your PATH and reports what would execute. whereis searches a fixed set of standard directories for binaries, source and manuals.
