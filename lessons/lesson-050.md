## Important concepts

### Hashing is not encryption

Encryption is reversible with a key. Hashing is a one-way transformation that produces a fixed-length digest. A login system hashes the submitted password and compares digests, so it never needs to store the original.

### Salts and slow hashes

A salt is a unique random value added before hashing, so identical passwords produce different digests and precomputed rainbow tables stop working. Password-specific algorithms such as bcrypt, scrypt and Argon2 also make each guess intentionally expensive.

## Practical notes

These reference commands show the difference between fast general-purpose hashes; they are not password storage recommendations.

| Command | What it does |
| --- | --- |
| `echo -n "password" \| sha256sum` | Compute a SHA-256 digest of a string. |
| `echo -n "password" \| md5sum` | Compute an MD5 digest (obsolete for security). |
| `sha256sum file.iso` | Hash a file to verify integrity. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Can a hash be reversed?

Not by design. Attackers instead guess candidate passwords, hash them and compare. Weak passwords can be recovered this way quickly.

### Why is MD5 unsuitable for passwords?

It is fast and collision-prone, which makes large-scale guessing cheap. Password hashing should be deliberately slow and salted.
