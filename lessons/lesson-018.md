## Important concepts

### Directories need execute

A directory's execute bit controls whether you can traverse it. If a parent directory lacks execute for your account, you cannot reach a file inside even when the file itself is readable. Permission problems often live one level above the file named in the error.

### Recursive changes propagate

chmod -R applies the same mode to every item below a path. It is fast and blunt: executable bits may land on data files and sensitive subfolders may become readable. Apply it deliberately and verify with find or ls -l.

## Practical notes

Use a disposable tree under your home directory to practise each scenario.

| Command | What it does |
| --- | --- |
| `chmod u+x backup.sh` | Make a script executable by its owner. |
| `chmod 600 secrets.txt` | Allow only the owner to read and write. |
| `chmod -R 750 shared/` | Apply a consistent mode to a folder tree. |
| `sudo chgrp analysts shared/` | Give a group ownership of a folder. |
| `ls -ld shared/` | Inspect directory permissions and ownership. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### Why can I read a file but still get permission denied?

One of the parent directories probably lacks execute permission for your account. Check the path one level at a time with ls -ld.

### How do I share a folder with only one group?

Set group ownership with chgrp and use a mode such as 750 or 770 so group members get the access they need without exposing the folder to everyone.
