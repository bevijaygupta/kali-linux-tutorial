## Important concepts

### Exploit plus payload

An exploit delivers code by abusing a vulnerability. A payload is what runs after successful delivery, such as a shell. The same exploit can often use several payloads, which is why configuration is a two-part decision.

### A framework, not a target list

Metasploit organises modules and sessions but does not find targets for you. Reconnaissance and scanning identify the service and version; the framework helps you act on that information within an authorized scope.

## Practical notes

Practise navigation against Metasploitable in an isolated lab. These commands change no target until you run an exploit.

| Command | What it does |
| --- | --- |
| `msfconsole` | Start the Metasploit console. |
| `search vsftpd` | Search for modules related to a service. |
| `use auxiliary/scanner/ssh/ssh_version` | Load an auxiliary scanner module. |
| `show options` | Display the module's required settings. |
| `set RHOSTS 192.168.56.101` | Set the target host for the loaded module. |
| `set PAYLOAD linux/x64/meterpreter/reverse_tcp` | Select a payload for an exploit module. |

Commands are shown for study. Run them only in your own lab, read the manual page (`man <tool>`) first, and check every option before executing anything.

## FAQ

### What is Metasploitable?

A deliberately vulnerable virtual machine maintained for practising exploitation in an isolated lab.

### Does Metasploit require a database?

It works without one, but the PostgreSQL database enables workspace management and faster search of hosts, services and credentials.
